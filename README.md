# Радар дедлайнов

«Радар дедлайнов» помогает понять, к каким учебным срокам не хватит времени. Программа читает CSV со списком заданий, оценкой трудозатрат и статусом, затем строит отчёт с просроченными задачами и дефицитом минут на каждую дату выбранного периода.

## Запуск

Нужен Python 3.12 или новее. Из корня репозитория запустите демо с фиксированной датой, чтобы получить тот же результат, что и в Project CI.

```bash
python -m deadline_radar data/demo.csv --as-of 2026-11-23 --days 7 --daily-minutes 90
```

Читайте `dist/report.md` или используйте `dist/report.json` для дальнейшей обработки. Чтобы проверить свои задачи, передайте путь к своему CSV. По умолчанию расчёт начинается с текущей локальной даты, период составляет 7 дней, бюджет составляет 90 минут в день. Параметр `--out-dir` задаёт папку отчёта.

### Формат CSV

Файл использует UTF-8 и запятые. Первый ряд содержит заголовки. Поля с запятой заключаются в кавычки.

```csv
id,subject,title,due,minutes,status
lab-01,Программирование,Исправить тесты,2026-11-23,65,open
lab-02,Базы данных,"Составить запросы: JOIN, GROUP BY",2026-11-25,120,open
```

Для `id` нужно уникальное значение, для `due` нужна дата `ГГГГ-ММ-ДД`, для `minutes` нужно положительное целое число. Статус `open` означает, что работу ещё нужно выполнить. Статус `done` означает, что работа завершена. При ошибке программа сообщает имя файла и номер строки и завершает работу с ненулевым кодом.

### Как считается дефицит

Для каждой даты программа суммирует оставшиеся минуты по всем открытым заданиям со сроком до этой даты включительно. Просроченный остаток попадает в расчёт с первого дня. Доступное время равно дневному бюджету, умноженному на число календарных дней с начала периода. Положительная разница между требуемым и доступным временем показывает дефицит к сроку. Расчёт предполагает, что задания можно начинать заранее и делить работу на несколько дней.

На демонстрационных данных к 23 ноября нужно 105 минут при доступных 90, а к 25 ноября нужно 300 минут при доступных 270. Это видно в таблице отчёта и в полях `required_minutes`, `available_minutes` и `deficit_minutes` в JSON.

## Что разработано для задания

Проект создан с нуля. В него входят загрузка и валидация CSV, расчёт накопленной нагрузки, формирование отчёта в двух форматах и демонстрационный набор из восьми вымышленных задач. Автоматизация проверяет расчёт и командную строку, а отдельный workflow собирает отчёт на демонстрационных данных. Применение ИИ описано в [AI_MODELS.md](AI_MODELS.md).

## Quality CI и Project CI

| Workflow | Запуск | Результат |
| --- | --- | --- |
| [Quality CI](.github/workflows/quality-ci.yml) | Push, pull request и ручной запуск | Ruff проверяет код и форматирование. `unittest` на Python 3.12 и 3.13 проверяет расчёт нагрузки, обработку ошибочных строк и повторяемость вывода CLI. Падения проверок видны в статусе и журналах соответствующей задачи. |
| [Project CI](.github/workflows/project-ci.yml) | Push в `main` и ручной запуск | Программа строит отчёт по `data/demo.csv`. Markdown виден на вкладке **Summary** запуска. Markdown и JSON можно скачать в разделе **Artifacts** как `deadline-report`. |

Для воспроизведения Quality CI локально используйте следующие команды.

```bash
python -m pip install -r requirements-dev.txt
python -m ruff check .
python -m ruff format --check .
python -m unittest discover -v
```

Навигация для проверки работы находится в [SUBMISSION.md](SUBMISSION.md).
